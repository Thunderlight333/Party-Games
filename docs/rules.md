## 2. المواصفات التقنية الثابتة
- Vanilla JS + HTML + CSS فقط. **صفر مكتبات أو خطوط أو صور من الإنترنت**؛ يعمل 100% أوفلاين حتى بفتح `index.html` مباشرة.
- **مكان المشروع:** جذر المستودع `Thunderlight333/Party-Games` (مناسب لـ GitHub Pages مباشرة).
- **الفروع:** `site` (النسخة الكاملة المدموجة، ومنها يُنشر الموقع — كل التعديلات الجديدة عليه) · `ccr-54bbbeba-062m1k` (الأساسي: المرحلة 1) · `design` · فروع الألعاب للأرشيف: `game/huroof`، `game/feud`، `game/codenames`، `game/emperor`، `game/outsider`، `game/taboo`، `game/bid`، `game/wheel`، `game/mafia`، `game/pictures` (ملغاة).
- مرجع البنية التقنية وطريقة إضافة لعبة: `README.md` (يُقرأ قبل كل مرحلة).
- هيكل Modular: `core/` (المخزن، التوجيه، الصوت، المؤقت، الفرق، النوافذ) + `games/` (ملف لكل لعبة) + `data/` (بنوك الأسئلة داخل ملفات JS لتعمل بدون سيرفر).
- State Manager مركزي يحفظ في LocalStorage عند كل تغيير (نقاط، أسئلة مستخدمة، المؤقت، الدور الحالي...).
- Web Audio API لتوليد المؤثرات (Buzzer، صح، مؤقت، قلب بطاقة) بدون ملفات صوت.
- تصميم داكن زجاجي (Dark Glassmorphism)، RTL، متجاوب للجوال والتلفاز، مع Transitions. **للأداء:** بدون `backdrop-filter` ولا تمويه متحرك.
- أيقونات الأدوار والواجهة: SVG مرسومة داخل الكود.
- **قابلية إضافة ألعاب مستقبلاً:** سجل ألعاب (Game Registry)؛ كل لعبة تسجّل نفسها بملف واحد في `games/` + ملف بياناتها في `data/` + سطر في `index.html`، وتظهر تلقائياً في الرئيسية وتستفيد من الفرق والحفظ والإعدادات دون تعديل النواة. أي لعبة جديدة تُضاف كمرحلة مستقلة عند طلبي.
- **النشر:** موقع ثابت على GitHub Pages مع Service Worker (PWA) ليعمل أوفلاين بعد أول زيارة ويمكن تثبيته على الجوال. بعد أي تعديل: `node tools/build-sw.js`.

## 3. الأنظمة العامة (تستخدمها كل الألعاب)
- **الحفظ والاستئناف:** شريط/زر واضح "لديك لعبة قيد اللعب — رجوع". عند فتح لعبة أخرى أو ضغط "إنهاء" تظهر رسالة تأكيد.
- **نظام الفرق الديناميكي:** أي عدد فرق، اسم ولون (Color Picker) لكل فريق، أسماء لاعبين، نقل لاعب بين الفرق أثناء اللعب.
- **إعدادات لكل لعبة:** مؤقت الدور، و"إعادة اللعب وتوزيع عشوائي" مع تحذير تأكيد.
- **QoL:** زر "تغيير السؤال/التحدي" في كل لعبة، ملء الشاشة، ومنع تكرار الأسئلة (تتبع المستخدم منها حتى ينفد البنك ثم يُعاد خلطه).

- تحدي المئة: لا خانة كتابة للإجابة؛ المقدّم يقلب البطاقة بنفسه.
- الملفات في جذر المستودع. بعد الدمج: كل التعديلات على `site`.
- ملفات التوثيق بصيغة Markdown (`rules.md` و`progress.md`).

المتطلبات الأساسية والأنظمة العامة (Global Systems & QoL):
1. نظام الحفظ التلقائي (Auto-Save & State Management): يجب ربط كل حركة وتقدم في أي لعبة بـ LocalStorage لحظياً. إذا تم إغلاق الصفحة أو تحديثها بالخطأ، يجب أن يستعيد التطبيق حالة اللعبة تماماً (نقاط الفرق، الأسئلة المجابة، المؤقت، الخ). يمكنك إضافة زر واضح يخبرك انه هناك لعبة قيد اللعبة ويطلب منك الرجوع واذا حاولت الدخول الى اي لعبة او ضغط زر انهاء لها تجيك رسالة تأكيد على الاغلاق
