1. قوانين العمل (إلزامية)

  1. قبل أي مرحلة: يشرح Claude باختصار ما سيفعله، ثم ينتظر موافقتي ولا يبدأ قبلها.
  2. توفير التوكنز: ردود مختصرة، بلا شرح زائد، بلا قراءة ملفات غير لازمة، وتنفيذ مرحلة واحدة فقط في كل مرة.
  3. الرد دائماً بالعربية.
  4. لا commit ولا push ولا PR ولا أي تغيير على GitHub إلا بإذن صريح مني في نفس الرسالة.
  5. بعد كل مرحلة: تحديث جدول المراحل في هذا الملف (الحالة) وإعادة توليده PDF، وتحديث ملف التقدّم docs/progress.md، وإرسالهما مع zip.
  6. عدم كسر ما سبق: كل مرحلة تضيف لعبتها كوحدة مستقلة دون تعديل ألعاب أخرى إلا للضرورة.

2. المواصفات التقنية الثابتة

  • Vanilla JS + HTML + CSS فقط. صفر مكتبات أو خطوط أو صور من الإنترنت؛ يعمل 100% أوفلاين حتى بفتح index.html مباشرة.
  • مكان المشروع: جذر المستودع Thunderlight333/Party-Games (مناسب لـ GitHub Pages مباشرة).
  • الفروع: ccr-54bbbeba-062m1k (الأساسي: المرحلة 1) · site (النواة/الموقع الأساسي) · design (التصميم) · فرع لكل لعبة: game/huroof، game/pictures، game/feud، game/mafia، game/outsider، game/emperor، game/codenames، game/taboo.
  • مرجع البنية التقنية وطريقة إضافة لعبة: README.md (يُقرأ قبل كل مرحلة).
  • الحاوية مؤقتة: بعد كل مرحلة تُرسل نسخة zip للمستخدم. عند بدء جلسة جديدة يرفع المستخدم آخر zip (أو يُسحب من GitHub).
  • هيكل Modular: core/ (المخزن، التوجيه، الصوت، المؤقت، الفرق، النوافذ) + games/ (ملف لكل لعبة) + data/ (بنوك الأسئلة كـ JSON داخل ملفات JS لتعمل بدون سيرفر).
  • State Manager مركزي يحفظ في LocalStorage عند كل تغيير (نقاط، أسئلة مستخدمة، المؤقت، الدور الحالي...).
  • Web Audio API لتوليد المؤثرات (Buzzer، صح، مؤقت، قلب بطاقة) بدون ملفات صوت.
  • تصميم داكن زجاجي (Dark Glassmorphism)، RTL، متجاوب للجوال والتلفاز، مع Transitions.
  • أيقونات الأدوار والواجهة: SVG مرسومة داخل الكود.
  • قابلية إضافة ألعاب مستقبلاً: سجل ألعاب (Game Registry)؛ كل لعبة تسجّل نفسها بملف واحد في games/ + ملف بياناتها في data/ + سطر واحد في index.html، وتظهر تلقائياً في الرئيسية وتستفيد من الفرق والحفظ والإعدادات دون تعديل النواة. أي لعبة جديدة تُضاف كمرحلة مستقلة عند طلبي.
  • النشر: موقع ثابت جاهز للرفع على GitHub Pages. يُضاف Service Worker ليعمل أوفلاين بعد أول زيارة ويمكن تثبيته على الجوال (PWA).

3. الأنظمة العامة (تُبنى في المرحلة 1 وتستخدمها كل الألعاب)

  • الحفظ والاستئناف: شريط/زر واضح "لديك لعبة قيد التشغيل — رجوع". عند فتح لعبة أخرى أو ضغط "إنهاء" تظهر رسالة تأكيد.
  • نظام الفرق الديناميكي: أي عدد فرق، اسم ولون (Color Picker) لكل فريق، أسماء لاعبين، نقل لاعب بين الفرق أثناء اللعب.
  • إعدادات لكل لعبة: مؤقت الدور، و"إعادة اللعب وتوزيع عشوائي" مع تحذير تأكيد.
  • QoL: زر "تغيير السؤال/التحدي" في كل لعبة، ملء الشاشة، ومنع تكرار الأسئلة (تتبع المستخدم منها حتى ينفد البنك ثم يُعاد خلطه).

6. ملحق: نص الطلب الأصلي كاملاً (المرجع النهائي للتفاصيل)

أريد إنشاء تطبيق ويب متكامل وشامل بأسلوب (Offline-First Arabic Party Games Hub) يعمل كـ "مركز ألعاب للجمعات والمجالس". التطبيق يجب أن يعمل 100% أوفلاين كـ (Single Page Application) بملف واحد أو هيكل محلي دون أي مكتبات خارجية تتطلب اتصالاً بالإنترنت، وبتصميم غامق أنيق (Dark Glassmorphism UI) داعم للاتجاه من اليمين لليسار (RTL). المتطلبات الأساسية والأنظمة العامة (Global Systems & QoL): 1. نظام الحفظ التلقائي (Auto-Save & State Management): يجب ربط كل حركة وتقدم في أي لعبة بـ LocalStorage لحظياً. إذا تم إغلاق الصفحة أو تحديثها بالخطأ، يجب أن يستعيد التطبيق حالة اللعبة تماماً (نقاط الفرق، الأسئلة المجابة، المؤقت، الخ). يمكنك إضافة زر واضح يخبرك انه هناك لعبة قيد اللعبة ويطلب منك الرجوع واذا حاولت الدخول الى اي لعبة او ضغط زر انهاء لها تجيك رسالة تأكيد على الاغلاق 2. الإدارة الديناميكية للفرق (Dynamic Team System): نظام يتيح إضافة أي عدد من الفرق (فريقين، 3، 4، أو أكثر) للألعاب الجماعية. يجب أن يوفر النظام: - اختيار وتغيير لون مخصص (Color Picker) واسم لكل فريق. - إمكانية نقل أو تبديل أي لاعب من فريق إلى آخر بسلاسة في منتصف الجولة. 3. الإعدادات المخصصة لكل لعبة (Per-Game Settings): لوحة إعدادات مستقلة داخل كل لعبة تتيح التحكم الدقيق بـ: - توقيت الدور (Timer) الخاص بتلك اللعبة. - خيار "إعادة اللعب وتوزيع عشوائي" (Reset & Shuffle) لإعادة تصفير اللعبة الحالية مع خلط وتوزيع أماكن الحروف/البطاقات/الأسئلة بشكل عشوائي تماماً. 4. ميزات تحسين تجربة المستخدم (QoL): - زر مخصص لـ "تغيير السؤال/التحدي" (Skip/Change) في كل الألعاب لتجاوز السؤال الحالي واستبداله بسؤال آخر فوراً. - وضع ملء الشاشة (Full-Screen Mode) مخصص للصور أو الواجهات التي تتطلب تركيزاً بصرياً. الألعاب المطلوبة وتفاصيلها الميكانيكية: أولاً: ألعاب التحديات والفرق 1. مسابقة الحروف (حروف مع عزيز): - شبكة حروف هجائية (أ-ي). عند النقر على حرف تظهر نافذة بسؤال ذكي. - أزرار لتلوين الحرف بلون الفريق الفائز (حسب نظام الفرق الديناميكي). - زر "تغيير السؤال" في نافذة الحرف لاستبدال السؤال فوراً إذا لزم الأمر. - زر "إعادة التوزيع" لخلط أماكن الحروف والأسئلة عشوائياً لكن يجب أن يكون هناك تحذير قبل إعادة التوزيع لعدم توزيعها عن طريق الخطأ. 2. تحدي الصور (تخمين الصورة وتجميع الكلمة): - عرض صورة مع أجزاء ومقاطع كلمات مبعثرة كأزرار (Chips). - زر مخصص لتكبير الصورة (Full-Screen) لرؤية التفاصيل بوضوح. - زر لتغيير الصورة/التحدي. 3. تحدي المئة (Family Feud): - محاكاة للوحة البطاقات المقلوبة مع النقاط المخفية. - نظام أخطاء (Strikes) ❌ مع مؤثر صوتي (Buzzer)، وزر لتغيير السؤال بالكامل. ثانياً: الألعاب المعتمدة على الاستنتاج والتخفي 4. لعبة "مافيا" (Mafia) - بنظام "اللعب بالتمرير" (Pass-and-Play) ليتمكن الهوست من اللعب: - أيقونات بصرية مميزة (Unique SVG/Icons) لكل دور (المافيا، الطبيب، المحقق، المواطن). - مرحلة توزيع الأدوار: تظهر شاشة بأسماء اللاعبين؛ يظهر اسم اللاعب الأول، يضغط "إظهار دوري"، يرى دوره وأيقونته، ثم يضغط "إخفاء وتمرير" للاعب التالي. - مرحلة الليل (Night Phase): تمرر الشاشة للاعبي المافيا فقط لاختيار الضحية عبر واجهة التطبيق، ثم للطبيب لاختيار من سينقذ، ثم للمحقق، دون أن يعرف الهوست أو أي لاعب آخر من اختار من. التطبيق يحلل النتائج ويظهر حصيلة الليل في "النهار". - إعدادات لتعديل عدد الأدوار حسب عدد اللاعبين وزر لتغيير السيناريو. 5. لعبة "برا السالفة" (Out of Context): - تمرير الجهاز بين اللاعبين لعرض الكلمة السرية للجميع باستثناء لاعب يظهر له "أنت برا السالفة". - زر لتغيير التصنيف والكلمة فوراً إذا كانت غير مناسبة. 6. إمبراطور الكلمات (لعبة الكلمات): - واجهة إدخال يكتب فيها كل لاعب (أو الهوست) الكلمات الخاصة بكل شخص. - التطبيق يقرأ الكلمات عشوائياً (أو يعرضها للهوست ليقرأها). - واجهة تفاعلية لاختيار "اللاعب المهاجم" و"اللاعب المستهدف" والكلمة المخمنة، مع نظام إقصاء آلي ونقل الكلمات للرابح وتحديث الفرق إن لزم الأمر. ثالثاً: ألعاب إضافية مقترحة 7. العميل السري (Codenames بالعربي): شبكة كلمات 5x5. الهوست يرى "مفتاح الخريطة" السري لتصنيف الكلمات (ألوان الفرق، المدنيين، القاتل). 8. بدون كلام (Taboo): بطاقات تعرض كلمة رئيسية لشرحها و3 كلمات ممنوعة، مع مؤقت وزر لتخطي البطاقة (تغيير السؤال). لعبة تشبه تماما نظام لعبة codenames من حيث طريقة اللعب واجعلها متناسقة مع نظام الفرق لكن اجعل هناك اقتراح ان اللعبة تنلعب بفريقين فقط. خلي جميع الألعاب بمكتبة كبيرة من الاسئلة والصور لعدم تداخل وتكرار الاسئلة مع اللعب الطويل المتطلبات التقنية للمخرجات: الرجاء بناء هيكل متين (Modular) بـ Vanilla JS يتعامل مع البيانات كـ JSON، ويستخدم Web Audio API للمؤثرات الصوتية. ركز جداً على نظام الـ LocalStorage ليحفظ حالة الـ State Manager بشكل دائم، مع توفير CSS متطور يدعم التحولات (Transitions) والمظهر الزجاجي الفاخر. جزء العمل الى مراحل، كل مرحلة تتضمن لعبة واي شيء تريده انت مثل الواجهة، لكن اجعل الواجهة وكل ما تحتاجه لتفعيل وافتتاح الموقع هو أول مرحلة. لا اريد ان تصرف توكنز كثيرة لهذا السبب، قبل ان تبدأ اخبرني دائما ماذا ستفعل، وانتظر موافقتي وبعدها ابدأ، ضع هذه القوانين في ملف pdf لكي ارسله لك كل مرة اسوي compact الشات. — إضافات لاحقة من المستخدم — • إضافة قابلية إضافة ألعاب مستقبلاً عند الطلب. • الموقع سيُرفع على GitHub في مستودع منفصل وحساب منفصل تماماً، ولا يُرفع شيء إلا بإذن صريح. • الملفات في جذر المستودع، وفرع مستقل لكل لعبة وللموقع الأساسي وللتصميم.
